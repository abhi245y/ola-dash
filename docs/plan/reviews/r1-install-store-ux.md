# Review r1: install, store, rider UX (Fable)

Reviewed: PLAN.md draft r1. Findings ranked, most important first. Line numbers refer to draft r1.

1. **E5.S2 installer hides the hardest step, which is not needed.** Root adb on Gen 1 is a per-boot patched `adbd` restored by an owner-built boot helper (13-gen1-root-adb.md:37-69, 105-117). Every install step (`pm install`, `pm disable-user`, `cmd package set-home-activity`, `appops set`, `cmd notification allow_listener`) runs through the vendor diagnostics service: root, unauthenticated, IPv6 TCP 50005 (02-root-over-ipv6.md:5-7, 40-41), works in `cust` mode (03:41-43), pushes files in base64 chunks (scripts/ola.py:200-209). Python needs `grpcio` (no stdlib HTTP/2). Change: preflight on the diagnostic channel, adb optional, IPv6 discovery step, AC "fresh MoveOS 5 scooter on the same network, no prior tooling, one command". Disclose that the vendor service is unauthenticated root and an OTA could remove it.
2. **E5.S1 watchdog location is already known.** No init hook (13:129-131); root-at-boot = APK with `BOOT_COMPLETED` dialling `[::1]:50005` (14-gen1-boot-helper.md, 17:22-43). Heartbeat in host private dir needs root to read. Add T0: try `cmd package set-home-activity` without disabling the stock HMI; if it works, uninstalling the dash alone restores stock. Restore must be one typeable line, printed on the host fallback screen; phone path via the ola-s1-rea Android app (12-android-app.md).
3. **E4 store: add five cheap things.** (a) index `seq` + `expires`, reject lower seq, verify signature over raw bytes before parsing, index ≤ 1 MB. (b) two compiled-in Ed25519 keys (one offline), `kid` in the signature, revocation = host release without the key. (c) inflate-count zip bomb guard, image ≤ 2048×2048 by header, `animation-tick(` ≤ 3, probe compile on a worker with 10 s timeout (today `spin_on` on the UI thread, lib.rs:324-329), reserved ids `default`/`fallback`/`last-resort`. (d) runtime guard: frame time > 50 ms for 5 s after a switch reverts. (e) plugin CI dumps permissions; reject `SYSTEM_ALERT_WINDOW`, `BIND_ACCESSIBILITY_SERVICE`, `BIND_DEVICE_ADMIN`, `REQUEST_INSTALL_PACKAGES`, `PACKAGE_USAGE_STATS`, HOME activities. 2019 CA store: TLS failure is an error, never fall back to http.
4. **Themes can deceive.** A theme can draw a fake passcode keypad or a static speed. Add a "lock word" the owner sets at first run, shown only on the real host keypad and owner-PIN screen, never in the contract. Store rules: no PIN UI in themes; reviewers compare sim captures at fixed mock states against the mock values.
5. **Mod-author loop breaks with the release flavor.** `run-as` needs debuggable (plugins.md:37); cust-mode scooters have no adb. Add `installer push-theme <dir>` over the same gRPC channel, chown to the app uid, host rescans on switcher open, "sideloaded, unsigned" badge, same safe-unzip/probe path. Store needs Wi-Fi set up once; cellular data unmeasured.
6. **AA delivers less than asked.** Say plainly: 1.0 = Open Headunit in front + host dash bar; no AA cards inside a theme, no automatic connection, no guaranteed helmet audio. Dash bar default 64 px, speed digits ≥ 44 px, opaque, options 48/64/80. Spike tries a receiver resolution that leaves the bar margin. A vehicle lock while another app is in front brings the host lock screen forward.
7. **One theme switcher, plus a safety net.** Switcher is both a screen and a settings section; make it one. After a switch: "Keep this theme? Reverting in 10 s". Check for `Sensor.TYPE_LIGHT`; prefer lux over the clock (headlight is always on). `preview.png` = riding state with overlay.
8. **Settings IA and launcher for gloves and sun.** Rail-and-pane, rail rows ≥ 72 px, ≤ 7 items: Theme, Display, Android Auto, Plugins, Apps, Security, About (logs inside About). Launcher: 5 columns, 96 px icons, ≥ 24 px labels, hide `com.olaelectric.*`, `com.ola.*`, Settings, dash, watchdog by default; "show system apps" behind owner PIN. First-run card: theme, night mode, optional PIN, lock word. Hub button = the strip's own 72 px end cell.
9. **OTA never mentioned.** Other owners' OTA is live; it can re-enable the stock HMI or remove the diagnostic service. Installer `status` reports OTA state; dash and installer never touch it; docs say re-run install after an OTA.
10. **"Proper lock" expectations.** State: lock = stock passcode flow styled by the theme + optional owner PIN for dash settings; no phone-as-key, no remote lock. Drop now-playing from the lock screen.

Verdict: the install story is the biggest gap; a gRPC-only installer with uninstall-as-recovery is cheaper than what is written. Store needs five small additions. AA and lock need plain expectations, and the mod-author loop needs `installer push-theme`.
